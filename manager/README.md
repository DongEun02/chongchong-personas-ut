# Chongchong AI UT 관리 사이트

별도 패키지 설치와 모델 API 키 없이 사용하는 로컬 관리 화면이다. Node.js 22 이상에서 실행한다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:4310 을 연다. 종료는 실행 터미널에서 Ctrl+C다. 기본 포트를 바꾸려면 `PORT=4311 npm start`로 실행한다. 서버는 127.0.0.1에만 연결하며 외부 네트워크에서 접근할 수 없다. 별도 인증이 없으므로 공개 서버에 올리거나 외부에 포트를 열지 않는다. 자동 Aside 연동·모델 API 호출·브라우저 자동 실행 기능은 없다.

## 사용 순서

1. **페르소나**에서 실제 선정한 `personas.json`을 가져온다. 현재 원본 배열은 비어 있으므로 초기 대기 목록은 생성할 수 없다. 실제 선정 시각과 원본 필드를 채워야 한다. 리비전을 확보하지 못했다면 null로 보존하며 UI에 미확정으로 표시한다. 기존 파일은 `.ai-ut/`에 백업한 뒤 교체한다. 출처 검증은 사용자가 수행한다. 이미 만든 대기 지시문에는 당시 원문을 보존하므로 원문을 바꿨다면 해당 대기를 취소하고 다시 만든다.
2. **실행 대기 목록 → 실험 준비하기**에서 페르소나·TASK·버전·반복 차수를 선택한다. 반복 차수는 해당 묶음에 부여할 차수이며 반복 횟수 전체를 결정하는 설정이 아니다. 최초 파일럿은 선정한 3명과 T01/T02/current만 선택한다. T01은 오프셋 포함 기준 시각이 필수다. 대기를 만들 때 해당 원문과 조건의 지시문 스냅샷을 저장한다.
3. **지시문 보기**에서 복사하고 **새 Aside 대화**에 전달한다. 사이트가 Aside에 요청을 보내지 않는다. 실행 전에 검증자가 시작 화면·계정·테스트 데이터·정답표를 준비한다. 지시문에는 개선 가설과 검증자용 정답을 넣지 않는다. T03 초대 링크와 T04 필수 생성 값·테스트 전달 창구 등은 안전하게 별도 제공한다.
4. 같은 화면에서 `result.json`, `actions.json` 빈 양식을 각각 다운로드한다. 실행 식별값만 채워져 있고 status는 not_started, success와 수치는 null이다. 실제 실행 뒤 기록하고 검증자가 판정한다. 기록 규약은 루트 README와 tasks 문서를 따른다.
5. **실험 결과 → 결과 가져오기**에서 같은 실행의 `result.json`, `actions.json`, 민감정보를 가린 PNG/JPEG/WebP를 모두 선택한다. 미실행 양식은 등록하지 못한다. 캡처는 개당 5MB, 총 파일 17MB 이하이며 30개까지 지원한다. 캡처 파일명은 영문·숫자·밑줄·하이픈·점으로 작성한다. `verification.evidenceFiles`는 함께 가져오는 캡처의 파일명 배열이다(예: 상대 경로 없이 파일명만). 캡처가 없어도 JSON 두 개는 필요하다.
6. TASK·버전별 성공률, 성공 완료 시간, 행동 수, AI 용이성을 확인한다. A/B 비교는 양쪽 성공한 동일 페르소나·TASK·반복 차수만 묶는다. 행의 **기록·캡처**에서 대기 시간, 실패 분류, 관찰 행동, TASK별 추가 지표 원문을 확인한다. CSV 내보내기는 전체 결과를 포함한다.

## 저장 위치와 파일 보존

| 데이터 | 저장 위치 | 동작 |
| --- | --- | --- |
| 실제 선정 페르소나 | 루트 `personas.json` | 사용자가 가져오기로 확인했을 때만 변경, 기존 파일 로컬 백업 |
| 대기 목록·백업·임시 가져오기 | `.ai-ut/` | Git 제외. 브라우저 저장소가 아닌 로컬 파일 |
| 검증한 실행 | `runs/<runId>/result.json`, `actions.json`, 캡처 | 명시적으로 가져온 실제 기록만 저장. 기존 ID 덮어쓰기 금지 |
| 집계 CSV | 다운로드 `summary.csv` | `runs/`에서 동적으로 생성. 루트의 기존 CSV는 수정하지 않음 |
| 실행 양식·TASK 문서 | 기존 루트 파일 | 읽기만 수행 |

결과 JSON과 행동 JSON은 같은 runId여야 하며 대기 조건과 personaId/TASK/버전/차수가 다르면 거부한다. 대기 목록 없이 외부에서 수행한 실제 실행도 규약에 맞으면 가져올 수 있다. 원문·검증 근거의 진위까지 프로그램이 판단하지 않는다. 저장된 실제 결과는 UI에서 삭제하거나 수정하지 않는다. 잘못된 기록의 정정은 원본을 보존하고 검토 이력을 남기는 방식으로 처리한다.

유효 완료/실패는 같은 조건의 중복 대기를 막는다. invalid 실행은 기존 기록을 보존한 채 같은 차수로 새 대기를 만들어 재실행할 수 있다. 오류 원인과 이전 runId를 새 결과 notes에 연결한다. 동일 조건의 유효 결과를 중복으로 가져오는 것도 거부한다.

## 집계 범위와 한계

- status가 completed/failed인 실행만 유효 분모이며 invalid는 별도 표기한다.
- 페르소나 안에서 반복 평균을 먼저 구한 후 페르소나 간 평균을 낸다. 성공률 카드의 성공/유효 횟수는 실제 실행 수이고, 표시 백분율은 페르소나별 성공률의 평균이다.
- 시간은 성공 실행의 측정값만 사용하며 측정 수·성공 수·페르소나 수를 표시한다. null은 —이며 0으로 변환하지 않는다.
- A/B 카드의 시간은 공통 `timing.elapsedMs` 비교다. T03의 목적/전체 발견 시각과 T04의 구간별 시간 등은 상세 taskSpecific과 JSON에서 확인한다. 이 추가 지표의 자동 비교 차트는 아직 제공하지 않는다.
- 같은 TASK·버전 안에서도 모델·환경·프로토콜이 다른 결과가 있으면 섞어서 해석하지 않는다. 현재 필터는 TASK·버전까지만 제공하므로 모델과 프로토콜을 먼저 고정한다.
- 브라우저 동작 자동 측정, 초대 전달, 계정·테스트 데이터 초기화, 성공 독립 검증은 자동화하지 않았다. Aside와 검증자가 맡는다.
- 캡처와 로그는 커밋 전 별도 검토한다. `.gitignore`가 파일 내용의 비밀정보를 제거하지 않는다.

## 개발 확인

```sh
npm test
node --check manager/server.mjs
node --check manager/public/app.js
```

프런트엔드는 표준 HTML/CSS/JavaScript, 서버는 Node.js 내장 모듈만 사용한다. TASK 실행자 지시문은 `manager/domain.mjs`에 정의되어 있다. `tasks.md`의 지시문·제한이 변경되면 이 정의도 함께 수정한다. 테스트의 메모리 내 수치는 집계 계산 검사용이며 실제 페르소나 또는 실행 결과 파일을 생성하지 않는다.

## 조건 미설정과 실행 전 검증

페르소나 가져오기는 `experimentalConditions` 전체 null 또는 개별 조건의 null을 허용한다. 미설정 원문도 보관할 수 있으며 화면에는 ‘미설정’으로 표시한다. 대기 생성 시에만 **선택한 페르소나**의 webProficiency, similarServiceExperience, priorExperienceWithTargetService 세 필드가 모두 설정되었는지 확인한다. 누락 시 `P02: experimentalConditions.webProficiency`처럼 personaId와 필드명을 함께 안내한다. 선택하지 않은 페르소나의 null은 대기 생성을 막지 않는다.

2026-11-04 사용자 승인으로 P01~P30 모두 웹 숙련도 ‘중간’, 유사 서비스 경험 ‘없음’, 대상 서비스 사전 경험 ‘없음’을 부여했다. 세 값은 **원본 데이터의 사실이 아닌 연구자가 부여한 가상 실험 조건**이다. 나이·직업이나 원문에서 추론한 값이 아니다. dataset 메타데이터와 모든 source 원문은 변경하지 않았다. 이 조건에서는 웹 숙련도에 따른 그룹 비교를 하지 않는다.

리비전이 null인 현재 선정 파일도 가져오기와 대기 생성을 허용한다. 리비전 값이나 원본 메타데이터를 프로그램이 추정해 채우지 않는다. 현재 데이터셋 limitations의 경험 미확인/null 설명은 원본에서 확인한 사실의 범위를 나타내며, 이후 연구자가 부여한 실험 조건과 구분한다.
