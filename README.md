# AI 페르소나 기반 사용성 실험

## 목적

- 확인하려는 사용성 문제: 마감 과제 발견, 내 스터디 목록 이동, 초대 스터디 개요 이해, 기존 과제에 신규 멤버 포함의 어려움

소요 시간은 인간의 수행 시간이 아닌 AI 에이전트 실행 시간이다.

- 실행마다 새 대화에서 시작한다.
- 이전 실행의 경로와 결과를 전달하지 않는다.
- 페르소나, 역할, 목표만 전달하고 정답 경로는 알려주지 않는다.
- 개선 전후 여부와 기대 효과는 실행 AI에게 알려주지 않는다.
- A와 B에 동일한 관찰·조작 도구를 제공한다.
- 성공 여부는 AI의 선언이 아닌 화면 또는 서비스 상태로 검증한다.
- 계정 비밀번호, 쿠키, 인증 토큰, 초대 토큰은 저장하지 않는다.

## 판정 규칙

### 성공

tasks.md에 정의한 성공 조건을 모두 충족한 경우.

### 실패

잘못 완료하거나 포기하거나 실행 제한에 도달한 경우.
기능 미지원도 실패로 기록하되 원인을 별도 분류한다.

### 실험 오류

브라우저 장애, 모델 호출 장애, 테스트 데이터 오류 등으로
정상적인 시도 자체가 불가능한 경우.
실패율 집계에서 제외하고 같은 조건으로 재실행한다.
원본 기록은 삭제하지 않는다.

### 불필요한 행동

- 목표와 관계없는 화면에 진입한 뒤 돌아온 행동
- 새로운 정보 없이 동일한 시도를 반복한 행동
- 잘못된 선택 때문에 취소하거나 수정한 행동

정상적인 확인, 유효한 대안 경로, 합리적인 오류 복구는 제외한다.
동일한 실수에 대한 중복 집계 기준: 하나의 행동에는 하나의 주된 사유만 부여한다. 잘못 진입한 행동과 복귀 행동을 동일 사건으로 묶고, 원인 행동만 불필요 행동으로 센다. 새 정보 없는 재시도는 각각 별도 행동으로 센다.

## 집계 규칙

- 성공률 = 성공 수 / 유효 실행 수
- 성공 완료 시간은 성공한 실행만 집계하고 성공 수를 함께 표시한다.
- 시간의 전후 비교는 A·B 모두 성공한 동일 페르소나를 별도 비교한다.
- 실패까지 걸린 시간은 완료 시간과 구분한다.
- 불필요 행동과 AI 용이성 점수는 유효 실행 전체를 대상으로 집계한다.
- 반복 실행 시 페르소나별 평균을 먼저 구한 뒤 전체 평균을 구한다.
- 결측값은 0으로 대체하지 않는다.
- 외부 대기 시간과 모델·도구 대기 시간은 가능한 범위에서 분리한다.

## 페르소나 선정 절차와 출처 표시

출처: NVIDIA, Nemotron-Personas-Korea, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). 선정 시 사용한 리비전과 날짜를 기록하고, 원문을 변형했다면 변경 내용도 명시한다. experimentalConditions는 연구자가 별도로 부여한 조건이며 NVIDIA 원본의 속성이 아니다.

1. 선정 전에 고정 데이터셋 리비전과 제한된 후보 추출 방법(제공된 소규모 표본 또는 공개 뷰어에서 확인한 후보)을 정한다. 전체 데이터 다운로드는 필요하지 않다.
2. 추출 범위·후보 수·정렬 기준·선정 규칙·사용한 난수 시드(사용 시)를 dataset.selectionCriteria에 남긴다. 뷰어의 첫 행만 골랐다면 편의 표본임을 기록한다.
3. 나이·직업·생활 배경의 다양성을 고려하여 중복 UUID 없는 30개를 선정한다. 대표성이나 한국 사용자 전체에 대한 일반화를 주장하지 않는다. 나이·직업만으로 숙련도를 단정하지 않는다.
4. 각 항목에 personaId와 source의 uuid, age, occupation, persona, professional_persona, skills_and_expertise, hobbies_and_interests를 원문에서 복사한다. 임의 UUID·원문 보충은 금지한다. 필수 원문이 없는 후보는 제외하거나 결측 근거를 남긴다.
5. 각 persona 항목의 구조는 `{personaId, source, experimentalConditions}`다. source는 위 4번의 7개 필드를 가지며 age는 원본 정수, 나머지는 원본 문자열을 유지한다. experimentalConditions에는 webProficiency, similarServiceExperience, priorExperienceWithTargetService를 기록한다. dataset.selectedAt은 실제 선정 시각(오프셋 포함 ISO 8601), revision은 실제 사용한 고정 리비전이며 미선정 상태에서는 둘 다 null이다.
6. 별도 실험 조건 webProficiency(낮음/중간/높음), similarServiceExperience(없음/있음), priorExperienceWithTargetService(없음 원칙)를 사전 배정한다. 웹 숙련도는 각 10명 배분을 제안하며 다른 조건의 배분도 선정 전에 고정한다. 원문과 충돌하는 설정은 피하고 배정 근거를 남긴다.
7. 동일한 30개를 모든 TASK와 버전에 사용한다. 멤버(T01/T02), 비가입자(T03), 운영자(T04) 역할은 TASK별로 부여한다. 파일럿은 선정된 30개 중 웹 숙련도 조건별 1명, 총 3명을 미리 지정한다.

## 실행 규모와 순서 통제

최초 파일럿은 3개 페르소나 × T01·T02 × current × 1회 제안 = 6회다. T03·T04는 설계만 준비하며 최초 파일럿에 포함하지 않는다. A/B가 확보되면 동일 조건을 두 버전에서 실행한다. 본실험은 30개 × 4 TASK × 2버전 = 반복당 240회이며, 3회 반복하면 720회다. 반복 횟수는 아직 확정하지 않는다. 파일럿 후 제한과 양식을 확정하고 본실험 중 임의 변경하지 않는다. 변경하면 프로토콜 버전을 올려 분리 보고한다.

A=개선 전, B=개선 후는 제품 담당자가 확인한 커밋·배포 URL·배포 시각으로 고정한다. current는 파일럿 당시 실제 대상 버전이며 자동으로 A가 되지 않는다. 현재 A/B와 current의 커밋 모두 미확정이다.

본실험은 페르소나별 AB/BA를 15명씩 배분하고 숙련도 조건 내에서도 균형을 맞춘다. TASK 순서는 4개 순환 순서(T01→T02→T03→T04 등)를 30명에 8/8/7/7명 배정하는 방식을 제안한다. 배정표와 시드 또는 결정 규칙을 실행 전에 고정한다. 매 실행은 새 대화이므로 앞 실행의 대화·정답·개선 가설을 전달하지 않는다. 재실행도 같은 배정 조건을 따른다.

## 초기화와 실행 환경 고정

검증자는 매 실행 전에 별도 테스트 계정/격리 데이터로 가입 상태, 역할, 제출 상태, 과제 대상자, 시작 화면을 복원한다. 비밀번호·쿠키·토큰을 기록 파일에 넣지 않는다. T03의 가입과 T04의 생성·초대는 향후 실험 환경에서만 수행하며 이번 준비 작업에서는 변경하지 않는다.

새 브라우저 프로필 또는 Aside에서 가능한 독립 세션을 사용한다. 프로필 분리가 지원되지 않으면 쿠키·스토리지·방문 이력의 안전한 초기화 절차를 먼저 확인한다. 계정 로그인과 온보딩 완료는 검증자가 같은 절차로 준비하며 시간·행동 집계에서 제외한다. T02는 초기화 후 고정한 상세 URL을 직접 열어 시작해 이전 TASK의 목록 방문 이력이 남지 않게 한다. 뒤로가기가 유효한 실제 도착 경로이면 성공으로 인정한다.

화면 크기, Chrome 버전, ko-KR, Asia/Seoul, Aside 버전, 계정에서 표시되는 모델명, 관찰/조작 기능을 기록하고 A/B에서 같게 유지한다. 지원되지 않는 도구 대기 측정은 추정하지 않고 null로 남긴다. Browser Use, Cypress, Playwright, 외부 모델 API, 유료 서비스를 새로 설치·연결하지 않는다.

## 실행자에게 전달하는 정보

선정된 원문 페르소나, 별도 부여한 실험 조건, TASK 역할, tasks.md의 실행 지시문, 필요한 기준 시각, 허용 조작·제한만 전달한다. 제공 가능한 도구를 짧게 안내하되 메뉴 이름이나 정답 경로는 알려주지 않는다. 실행마다 전달한 전체 문구를 promptDelivered에 민감정보를 가려 기록한다. 검증자 전용 정답, 개선 가설, A/B 의미, 소스 조사 내용은 전달하지 않는다. 초대 링크는 실행 시 안전하게 전달하고 로그에는 토큰을 가린다.

## 행동과 시간 측정 규약

행동 1회는 관찰 가능한 하나의 조작이다. 클릭·링크 열기·입력 필드 하나에 연속 입력·스크롤 한 번·뒤로가기·새로고침·명시적 화면 관찰 요청·대기 요청·최종 답변 제출을 각각 1회로 센다. 복합 도구 호출은 실제 하위 조작으로 나눈다. 자동 스크린샷/자동 반환 관찰과 모델 내부 처리는 별도 행동으로 세지 않는다. 제한 판정은 이 단위를 사용한다. TASK 시간과 행동 집계는 준비 완료 후 목표 전달부터 시작한다.

각 행동은 step, timestamp(오프셋 포함 ISO 8601), elapsedFromStartMs, pageBefore(민감 쿼리 제거), action:{type,target,inputRedacted}, observationAfter, screenshot(가림 처리 후 상대 경로), review:{isUnnecessary,category,reason,reviewedBy}를 갖는다. action에 executionSucceeded(true/false/null)를 추가해 조작 실행 성공과 불필요 여부를 분리한다. review의 미판정 값은 전부 null이며, 판정 후 isUnnecessary는 true/false다. 민감한 입력은 실제 값 대신 `[가림]`으로 기록한다. 내부 사고 과정은 요구하거나 저장하지 않고 화면·행동·짧은 관찰만 남긴다.

불필요 행동 category는 unrelated_navigation / redundant_retry / mistaken_selection 등으로 사후 검증자가 부여한다. 뒤로가기 자체, 정상 확인, 유효한 대안, 합리적인 오류 복구는 자동 감점하지 않는다. 미검토 실행의 unnecessaryActionCount는 null이며 모든 행동 검토 후 true 수를 집계한다. actionCount는 전체 기록 행동 수다. 검증자가 가능하면 버전 정보를 가린 행동 로그로 판정하고, 판단이 갈리면 근거와 최종 검토자를 남긴다.

timing.startedAt은 준비 완료 화면에서 목표를 전달한 시점, endedAt은 최종 답변/목표 달성/포기/제한 도달 시점이다. 사후 검증과 용이성 질문 시간은 제외한다. elapsedMs는 두 시각 사이 총 경과 시간이며 모델·도구·외부 대기를 포함한다. modelAndToolWaitMs와 externalWaitMs는 겹치지 않는 구간만 기록하고 측정 불가 시 null이다. T04에서 외부 가입 대기는 externalWaitMs로 분리하며 이 구간은 능동 수행 제한에서 제외한다. 구간 경계와 관찰 근거는 taskSpecific에 남긴다. 시간 결측을 0으로 바꾸지 않는다. 제한 도달 시 다음 행동 없이 현재 상태로 판정한다.

## 상태·결과 기록 규약

| status | success | terminationReason | 적용 |
| --- | --- | --- | --- |
| not_started | null | null | 템플릿, 미실행 |
| completed | true | goal_met | 검증자가 성공 조건 전체 확인 |
| failed | false | goal_met / gave_up / time_limit / action_limit | 완료 선언이 틀린 경우 goal_met와 검증 실패를 함께 기록 가능 |
| invalid | null | infra_error | 인프라 장애, 잘못된 사전 데이터 등 실험 오류 |

완료 선언 후 오답은 failed로 판정한다. 유효한 기능 미지원은 failed이며 failureCategory=unsupported_feature다. 그 밖의 실패 분류는 discovery / incorrect_answer / incorrect_state / gave_up / limit 등으로 구분하고, 실험 오류는 infrastructure / fixture_error 등으로 구분한다. 성공과 미실행의 failureCategory는 null이다. verification에 검토자, 화면·권한 허용된 상태 확인 방법, 관찰 상태, 증거 파일을 남긴다. 기능 유무를 확인할 수 없으면 관찰과 미확정 원인을 구분하며 코드 없이 미지원이라고 단정하지 않는다.

AI 용이성 평가는 위 질문을 종료 후 묻고 1~5점과 관찰 근거를 기록한다. 응답이 없으면 null이다. 인간 만족도나 실제 사용자 SEQ 결과로 해석하지 않는다.

## CSV 매핑과 집계 상세

summary.csv는 실행별 1행이며 JSON의 runId→run_id, personaId→persona_id, taskId→task_id, repeat/status/success/version은 같은 의미다. timing의 elapsedMs/modelAndToolWaitMs/externalWaitMs를 각각 1000으로 나눠 elapsed_sec/model_tool_wait_sec/external_wait_sec에 넣는다. behavior의 두 count와 aiEvaluation.easeScore, failureCategory를 해당 열로 옮긴다. evidence_path는 실행 디렉터리 상대 경로이며 verification.evidenceFiles의 증거를 찾을 수 있어야 한다. null은 빈 셀, boolean은 true/false로 저장한다.

성공률 분모는 completed+failed이고 invalid와 not_started는 제외한다. failed를 빠뜨리지 않는다. invalid 원본은 보존하고 새 runId로 재실행하며 원인과 재실행 연결을 남긴다. current와 A/B, TASK, 프로토콜이 다른 실행은 섞지 않는다. 시도 수, 유효 수, 오류 수, 성공 수, 지표별 결측 수도 함께 보고한다.

시간 평균은 성공 실행의 실제 측정값만 사용하며 성공 수와 시간 표본 수를 함께 보고한다. 실패 소요 시간은 따로 보고한다. A/B 모두 성공한 동일 페르소나·TASK·반복 차수의 B−A 시간 변화도 별도로 보고하고 쌍 수를 명시한다. T03의 전체 정보 확인 시간도 같은 방식으로 비교한다. 성공자가 없으면 시간 평균은 결측이다. 반복 실행은 페르소나 내 성공률·행동 수·점수·성공 시간 평균을 먼저 구한 뒤 페르소나 간 평균을 구한다. 쌍 비교도 페르소나 내 차이 평균 후 전체 평균을 낸다. 결측을 대체하지 않고 각 평균의 표본 수를 명시한다. 소규모 파일럿으로 개선 효과를 확정하지 않는다.

## 개인정보와 인증정보

.env.example에는 키 이름과 안전한 자리표시자만 둔다. 실제 .env, 인증정보, 쿠키, 저장된 로그인 상태, 초대 토큰은 Git에 넣지 않는다. 로그·화면 캡처의 이메일, 이름, 초대 URL 쿼리, 토큰, 개인 데이터는 커밋 전에 검토하고 가린다. .gitignore는 이미 추적된 파일이나 캡처 속 민감정보를 보호하지 않는다. 원본 민감 캡처는 레포 밖 안전한 위치에 보관하고 이 레포에는 정제된 증거만 저장한다. 실제 서비스 사용자 데이터는 테스트 자료로 사용하지 않는다.

## 실행 전 TODO와 준비 순서

1. 제품 레포/설계 문서를 제공받아 라우트·화면·권한·과제 대상자·공지 로직의 근거를 보강한다. current 커밋과 배포 연결을 확인하고 이후 A/B를 명시한다.
2. 격리된 테스트 환경과 계정(멤버, 비가입자, 운영자, T04 신규 멤버)을 준비한다. production 계획을 유지한다면 실사용자 데이터에 영향 없는 격리·복원 가능성을 먼저 확인한다. 이번 작업에서는 계정을 생성하거나 데이터를 변경하지 않는다.
3. T01 기준 시각과 앱 시간 고정 방식, 과제 정답표, T02 다중 가입 목록과 시작 URL, T03 목적/요일/시간 정답, T04 원래 과제·대상자 검증 방법을 확정한다.
4. 고정 리비전의 실제 페르소나 30개를 선정하고 출처·조건·파일럿 3개를 기록한다.
5. Aside 연결 GPT 계정, 모델 표시명, 브라우저·관찰 기능, 세션 초기화와 시계 기록 방법을 확인한다. 반복 횟수·제한·실행 순서·검토자를 확정한다.
6. 매 실행 사전 점검→새 대화/세션→계정·데이터 복원→시작 화면 확인→목표 전달→행동 기록→독립 성공 검증→용이성 질문→민감정보 검토→CSV 반영 순서로 진행한다. 먼저 current에서 T01/T02 6회 파일럿만 실행한다.

실행 준비가 부족한 항목은 실험 오류를 만들기 전에 보완한다. 이번 변경은 문서와 양식 준비이며 실험 결과는 없다.

## 로컬 관리 사이트

Node.js 22 이상에서 `npm start` 후 http://127.0.0.1:4310 을 열면 페르소나 등록, 실행 대기 목록, Aside용 지시문 복사, 결과·캡처 가져오기와 집계를 사용할 수 있다. 별도 의존성 설치나 모델 API 키는 필요 없다. 실제 AI 실행은 Aside에 별도로 요청한다. 자세한 사용법·저장 위치·집계 범위는 [관리 사이트 안내](manager/README.md)를 따른다. 기존 실험 양식과 초기 빈 데이터는 유지한다.

### 현재 승인된 실험 조건 (2026-11-04)

사용자 승인에 따라 P01~P30 전체의 webProficiency는 ‘중간’, similarServiceExperience와 priorExperienceWithTargetService는 ‘없음’으로 설정했다. 이는 원본 사실이 아니라 연구자가 부여한 가상 실험 조건이다. dataset 및 source는 변경하지 않았다. 앞서 제안한 웹 숙련도별 각 10명 배분 대신, 현재는 30명 모두 동일한 조건을 사용한다. 따라서 숙련도 조건별 차이를 검증하는 설계는 아니다.
